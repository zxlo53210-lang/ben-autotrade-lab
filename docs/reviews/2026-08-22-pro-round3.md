## Findings and required disposition

### P0-1: deletion or rollback can re-arm the external opening anchor

The v1 store descriptor commits only the static store metadata. Removing the
opening record, experiment directory, shard, records tree, or replacing the
store with a copied pre-use descriptor can therefore make the same experiment
look unopened again. This is the upstream release blocker.

Required disposition: replace the claimed one-shot boundary with a design that
detects deletion and rollback using a verifiable append-only/WORM/monotonic
third-party witness. Adversarial tests must cover record, experiment, shard,
records-tree, whole-store, and coordinated repository/store rollback. Absence
or ambiguity must remain fail-closed and must never permit a second opening.

### P1-1: Linux runner may not define `TEMP` or `TMP`

The audit fixture directly indexes `os.environ["TEMP"]`, while the supported
Linux runner may expose only `TMPDIR` or Python's platform temp directory.

Required disposition: choose and explicitly pass a safe cross-platform temp
root, include it in local-path redaction, and prove ordinary plus isolated
source-bound tests on supported Windows and Linux/Python environments.

### P1-2: PAPER consumer accepts incomplete nested report evidence

The consumer verifies the top-level report schema and passing gate names, but a
self-hashed report can currently contain empty nested metrics, benchmark,
stress, holdout, and neighbor objects with manually true gates.

Required disposition: define exact nested schemas and types, reject non-finite
numbers and booleans masquerading as integers, rederive every gate from the
frozen config and nested evidence, and reject empty or forged evidence.

### P2-1: post-open manifest is not explicitly rebound field by field

After the durable external and local opening commitments, the finalizer reloads
the locked manifest but does not explicitly compare every returned manifest
commitment with the pre-open metadata and frozen selection.

Required disposition: perform an exact post-load comparison of the manifest
file hash, partition descriptors, normalized payload hash, lockbox ID, parent
manifest, paired descriptor, and all selection-bound data commitments before
evaluation.

### P2-2: bootstrap terminology must stay narrow

The shared circular moving-block bootstrap is a family-wise max-Sharpe
diagnostic. It does not fully correct selection bias for the primary
median-Calmar objective.

Required disposition: keep the diagnostic non-gating and describe it only as a
`family-wise max-Sharpe diagnostic`; never present it as a complete correction
for median-Calmar winner selection.
