## Findings and required disposition

### P0-1: a privileged operator can roll back the opening witness

The append-only WSL/ext4 inode is an effective defense against the unprivileged
laboratory runtime, but it is not an irreversible boundary against the
Windows/WSL operator. Linux root or `CAP_LINUX_IMMUTABLE` can clear the inode
flag and restore the pre-opening bytes in place while preserving the pinned
device and inode. Rolling back the complete WSL volume can restore the same
pre-opening state as well.

Required disposition: place the one-shot allocation boundary in retained WORM
storage, a TPM-backed monotonic service, or an independent remote append-only
witness. The independent boundary must reject reuse by each of
`experiment_id`, `lockbox_id`, and `holdout_commitment_sha256`. Its opening
receipt must be bound into the external anchor and local opened state. Its
finalization must bind the report hash, status and kind, opening receipt, local
opened-state hash, and anchor-record hash before local `FINALIZED` is written.
The local append-only inode may remain as defense in depth.

### P1-1: inherited temporary-directory values can escape redaction

The child audit environment replaces `TEMP`, `TMP`, and `TMPDIR` before the
redaction set is assembled. Consequently, nonempty inherited values can remain
in captured test output even though the child audit root is redacted.

Required disposition: snapshot every nonempty inherited temp path before the
child environment is rewritten, and redact both the inherited paths and the new
audit root in raw, slash-normalized, backslash-normalized, `repr`, and multiply
escaped forms. Cover three distinct nonempty values on Windows and Linux.

### P2-1: opening-burn documentation names the wrong anchor hash

The opening burn binds the primary anchor `store_id`, canonical store-descriptor
SHA-256, and opening commitment. The external opening-record hash cannot exist
until the later anchor step; it is then bound by local `HOLDOUT_OPENED` and the
witness finalization record.

Required disposition: make the witness documentation state that sequence and
distinguish the store-descriptor hash from the later opening-record hash.
